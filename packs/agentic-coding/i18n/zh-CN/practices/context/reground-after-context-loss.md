# 上下文丢失后重新立足事实

## 适用场景

在上下文被压缩或同一 Agent 的会话恢复后、任何实质性编辑或状态声明依赖保留下来的摘要之前，应用本条 Practice。跨 Agent 移交属于近似但不同的场景，需要对照当前权威、产物和证据验证交接声明。不要在上下文仍完整的中断前应用；那一时刻应创建持久 checkpoint。

## 具体指导

只把摘要用于定位权威任务来源、已接受的计划或决策、当前产物或 diff，以及已记录证据。重新阅读这些内容，与摘要比较，丢弃已被取代的假设，并陈述当前目标、未完成边界、有效证据和下一项有依据的行动。在实现继续前，以一份已经重新立足事实的工作状态为止点。

## 反模式

接受摘要中“功能已完成”的一句话，然后继续清理工作，尽管当前验收标准和 diff 显示授权流程从未实现或验证。

## 原因

摘要优化的是连续性，而不是权威性，并可能过度突出最近的实现细节。重新立足事实，可以在压缩后的错误变成更多工作的前提之前，恢复决定正确性的决策输入。

## 例外与边界

微小且无状态的任务，可能只需把摘要与当前产物快速比较。如果多个持久来源彼此冲突，应暂停以解决权威问题，而不是选择最符合摘要的版本。

## 示例

恢复一项 parser 重构后，Agent 重新打开语法需求和当前 diff。它发现核心语法检查仍有效，但从未验证 malformed-input 恢复，于是把状态从“已完成”改为“核心语法已验证”，并从这一修正后的边界继续。
