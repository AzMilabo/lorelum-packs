# 用户确认纠正后，把整项工作恢复到新基准

## 适用场景

用户、负责人或已接受规格已经纠正当前方向时使用。凡是目标、计划、代码、测试或文档中仍受旧理解影响的地方都要处理。来源仍冲突时先确认听谁的；未验证审查意见也不是已确认纠正。

## 具体指导

重读纠正内容和当前请求或规格，找出唯一依据是被否定理解的假设和产物，删除或修改它们；独立受需求或风险支持的行为和保护继续保留。最后写出当前任务陈述，明确哪些是恢复原范围，哪些是真正新增范围。

## 反模式

用户要求删除 Agent 在没有设计依据时加的辅助文字。Agent 删除后，又补全局负向测试、注释和设计规则，禁止所有类似页面出现辅助文字。这样看似防复发，却把一次恢复变成用户从未要求的新产品禁令。

## 原因

如果旧推理残留在计划、测试或文档里，纠正并未真正完成；但反向加永久禁令也同样会制造新偏移。

## 例外与边界

有权来源明确说明时，纠正可以建立持久契约。安全、隐私、合规、数据完整性和兼容性也可能独立要求长期保护。未受影响的工作应保留。

## 示例

用户说明需要的是屏幕状态徽标，而不是 Agent 从相邻功能推断出的每周邮件。Agent 删除调度器、邮件代码和邮件专用测试，保留徽标，也不记录对未来通知功能的通用禁令。
