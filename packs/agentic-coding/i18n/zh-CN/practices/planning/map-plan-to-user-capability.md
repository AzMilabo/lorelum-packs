# 按用户完成整条路径来检查计划

## 适用场景

计划跨越界面、服务、存储或策略，可能每个组件都有任务，却仍漏掉用户路径时使用。内部重构应映射必须保持的行为；实现结束后把已有结果对应到验收项，则属于验证阶段。

## 具体指导

从用户或调用方发起动作开始，沿所有必要边界追到可观察结果。把每项计划工作放到它支持的步骤上，找出没有负责人承担的必需步骤。补上职责，或明确缩小承诺；某一层完成不能证明整条路径完整。当所有必需步骤都有归属且没有解释不清的缺口时停止。

## 反模式

库存调拨计划包含请求接口和确认页，两者都容易开发测试，却因为预留库存属于另一个服务而漏掉它。所有清单项都能完成，但两名操作员仍可能同时卖出同一份库存。

## 原因

技术清单会奖励局部完成。从发起者走到结果，才能在部分实现变昂贵之前发现跨层缺口。

## 例外与边界

明确标注的分阶段交付可以只覆盖部分能力。基础设施和重构应映射它们保持的运行行为，不必虚构一个用户。

## 示例

密码重置仓库已有 token 创建和校验，单做 token 看起来接近完成。Agent 仍把请求、消息送达、token 校验、修改密码和注销旧会话全部映射到安全恢复账户，因此在编码前补上后两项，而不会把 token 服务称为完整能力。
