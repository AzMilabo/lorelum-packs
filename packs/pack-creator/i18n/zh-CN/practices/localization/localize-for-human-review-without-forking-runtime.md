# 本地化要便于人工审阅，但不能产生第二套运行时含义

## 适用场景

准备或更新另一语言的 companion 内容时使用。要让目标语言审查者自然理解，同时不能把译文变成第二套 canonical
Pack。Practice ID、运行时文件和预期决定仍由同一个英文 canonical 文件控制。

## 具体指导

翻译决定含义，不照搬英文语序。保持 Practice ID、anti-pattern
ID、trigger 条件、必需动作、停止点、例外、直接原因和案例关系不变；不熟悉的习语可换成目标语言的自然表达。按仓库布局把译文留在 canonical 运行时输入之外，并记录它对应的 canonical
revision。请目标语言审查者同时核对可读性和意义。所有译文都能追踪到一条当前 canonical
Practice 时停止，不能为“更实用”而新增本地语言专属运行时规则。

## 反模式

合规 Pack 的 canonical 规则要求按适用政策规定的期限保留客户记录，并在规则冲突时上报。某地区审查者希望看到具体数字，翻译者知道一个业务部门常用七年，于是只在译文加上“七年”。这个补充看似方便，却会变成第二条规则，并可能在政策变化后继续存在。

## 原因

自然译文能帮助人发现原指导是否含糊或有领域错误；含义分叉则使同一 ID 在不同语言里要求不同决定，也失去唯一修正位置。

## 例外与边界

译文可以用明确标注为非 canonical 的说明解释术语、法规名称或案例，但不能改变决定。真正影响运行时的地区规则应成为带明确 trigger 的 canonical
Practice 或独立 Pack。本条不要求逐句对齐。

## 示例

数据库运维 Pack 在恢复访问控制时使用 “fail
closed”。中文直译不清楚，翻译者改成：“无法确认权限状态时，继续拒绝访问，并请操作人员处理。”ID 不变，示例仍保持相同恢复顺序，本地化记录指向已审查 revision，也没有把中文文件放进运行时 Pack 根目录。
